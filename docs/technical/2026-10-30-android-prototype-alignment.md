# Android 按统一原型对齐

日期：2026-10-30。固定基线为 `design/prototype-v3/index.html`，基线提交 `96c26d7`。本次修改正式实现，不另建或修改设计原型。

## 已修正的差异

| 区域 | 原实现的问题 | 本批实现 |
| --- | --- | --- |
| 页头与输入 | 手机沿用桌面字号 / 间距 | 手机页头 32/40、说明 12/20，主内容上下留白按手机原型；输入时收起页头与底栏，保留退出入口 |
| 最佳匹配 | 封面 64 方形、内边距过大、正文偏大 | 封面 72×88、内边距 12、手机正文与操作尺寸；真实已知分 P 数才显示 |
| 列表 | 两行大标题、行高偏大 | 手机单行省略标题、较紧凑行高与说明字级 |
| 迷你播放器 | 额外“下一首”、容器和主按钮样式不同 | 仅保留播放 / 队列，使用封面配色的 secondary container、相同圆角与尺寸 |
| 音乐库 | 仅有简化收藏列表 | 收藏摘要与收藏 / 歌单 / 最近播放分类；最近播放暂存会话内，保留具体 cid。歌单 / 批量播放仍未开放，不显示虚构列表 |
| 设置 | 缺少分组图标、主题用开关 | 按原型分组与图标，主题改选择菜单；账号与位置恢复明确标注未开放 |
| 内容操作与分 P | 手机仍用桌面锚点菜单、对话框边距不一致 | 手机居中操作弹层及原型边距；历史条目的“选择分P”独立请求原视频，不直接重播旧 P |
| 播放页 | 顶部与封面间距多占空间 | 手机顶部栏 / 间距独立，短屏按控件预留空间约束封面，保留滚动；歌词元数据与队列图标形状按基线调整 |
| 队列 | 高度过大、额外拖动条、行密度不同 | 按原型的高度上限、圆角、计数标签和行密度，保留播放 / 移除 |
| 搜索加载 | 搜索 / 分 P 读取 / 翻页共用结果卡上方横条 | 手机移除额外横条；初次搜索使用原型已有的搜索等待卡与取消操作 |

表中尺寸来自 RxPlayer 既有原型，是产品设计取值，不作为 Google 官方 token。实际系统安全区与字体设置由 Android 提供，真实封面及曲目信息不使用原型虚构数据替换。Windows 保留原布局分支。

## 检查与交付边界

- 初批 `:androidApp:assembleDebug`、桌面编译及 14 项播放 / 浏览状态测试通过；真实播放探针未启用，不重复音源 / 引擎全流程验证。
- 定向代码审查指出历史菜单“选择分P”误触发重播，已用独立回调修复并复查。
- 初批正式 APK 已安装启动。随后用户明确要求“你只管改完，编译，安装，我自己来审核”，因此停止后续逐页点击、截图及扩大 UI 回归。
- 搜索横条修订按同一原型处理，`assembleDebug` 成功后已重新安装并启动，交给用户审核；不记录为视觉验收通过。
- 歌单、账号、持久化和系统播放能力并未因布局对齐而完成。

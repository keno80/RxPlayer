# 完整歌曲资料多源接线

- 范围：视频歌曲补全的候选、封面、同步歌词；不接入 QQ / 酷狗音频播放或账号。
- 分支：`codex/song-catalog-sources`，基线 `bf5cd3e`。
- 顺序：QQ 音乐 → 酷狗 → 网易云 → LRCLIB。

## 行为

搜索聚合四个来源并按优先级排列；一个来源失败不阻止其他结果，没有任意成功响应才报告查询失败。QQ 返回完整 `title` 及版本限定，避免其简短 `name` 隐藏 DJ / Live 信息；酷狗保留歌曲名与后缀。各源候选有界，保留不同来源供人工选择，不用第一个平台的任意结果屏蔽后续正确版本。

QQ 使用已验证的移动搜索、原生 MID、专辑 MID 封面和 LRC；酷狗使用 HTTPS 歌曲搜索、原生 FileHash、歌曲封面及歌词；网易云保留原接口；LRCLIB 使用曲目搜索和指定记录读取。LRCLIB 无封面字段；没有封面时按优先级寻找唯一同录音资料，仍无可靠结果则保留视频封面。显式手选版本优先，歌词仍按既定优先级寻找完整歌手、标题、版本、±2 秒且唯一的记录，不将其他平台的 ID 当成本源 ID。

`SongCandidate` 增加 provider / providerId，key 为平台与原生身份组合，双端候选选择 / 已选标记及自动匹配复核均按 key。自动匹配在各平台内要求唯一合格项，再依优先级选择。原始视频 / cid、队列与播放位置不变。

SQLite schema 5 保存平台身份；旧歌曲补全 payload 没有 provider 时仍解释为网易云。升版本可阻止旧应用误将 QQ / 酷狗 ID 当网易云 ID。既有手选与恢复视频原信息的选择继续保留，不批量清空缓存。

仅 LRCLIB 的单条原始歌手署名允许按分隔符与另一端已知完整歌手数组比较，保留显示原文和含标点的乐队名；QQ / 酷狗 / 网易的权威数组必须完整匹配。该边界在审查中发现并有先失败、后修复的回归。

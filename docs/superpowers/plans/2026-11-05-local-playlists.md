# 双端本地歌单实现计划

**授权范围：** 用户确认继续双端共用歌单管理；先交付共享逻辑、本地测试和完整原型提案，正式页面等待原型确认。沿用现有工作区，新建 `codex/local-playlists` 分支。

**方案：** 扩展现有 LibrarySnapshot 和 SQLite 原子快照，不引入第二套数据库或云服务。歌单有稳定 UUID、名称及有序的具体 Bilibili 分 P 曲目，以 track.id 去重。同名歌单允许，名称去除首尾空白后为 1～40 个 UTF-16 单元。重命名 / 删除 / 移除 / 排序不改变正在播放的队列。播放歌单以列表快照替换队列并从首曲顺序播放；追加保留当前播放和已有顺序，按曲目身份去重；空歌单不改变队列。

**持久化：** schema 1 → 2 的事务迁移只新增歌单与成员表；旧收藏 / 历史 / 队列 / 设置不丢失。不保存临时流地址，不在迁移或读库时解析音频。未知高版本继续拒绝写入。

**原型：** 使用 m3-expressive 的卡片、列表、菜单和对话框指导，在 `design/prototype-v3/index.html` 的现有音乐库内更新：新建、详情、管理菜单、改名、删除确认、曲目移除 / 上下移、选 P 后添加、整单播放 / 追加。布局沿用现有主题与组件；这批原型属于待审核提案，不接正式 Compose 入口。

# 页面间距统一

- 分支：`codex/layout-spacing`
- 2026-11-13 用户回复「开始正式 UI 实现」，确认本版间距作为双端正式界面基线。
- 唯一审核入口：`design/prototype-v3/index.html`，版本 `spacing-20261106`。
- 范围：Android / Windows 搜索及异常态、音乐库与歌单详情、设置、播放 / 歌词、队列、内容 / 分 P / 歌曲匹配 / 歌单弹窗及底部浮岛。

## 依据与产品选择

**M3 依据：** `m3-expressive/references/layout.md` 的窗口边距：紧凑宽度小于 600dp 时为 16dp，其余为 24dp；分栏间距为 24dp。布局采用 4dp 增量与常用 8dp 基础网格；系统安全区域单独保留。

**RxPlayer 选择（不是 M3 统一强制值）：** 页面上下间距随页面外边距；页头至内容与区块之间为 24dp；区块标题至内容为 12dp；一般卡片内边距 16dp、紧凑列表仍按其自身结构；弹窗内容内边距 24dp，弹窗外安全间距随设备为手机 16dp / 桌面 24dp。小间距使用 4 / 8 / 12 / 16dp。

页面标题、列表 / 卡片边缘与底部播放器沿相同内容边界对齐。桌面播放页页头、左侧信息 / 控制和右侧歌词容器共享外边界，双栏之间 24dp。封面在左栏内居中，不强行左对齐。歌词容器内边距 24dp，高亮歌词继续按实际可视区域居中。

手机有歌词时封面仍延伸至顶部及左右边缘，并渐变到下方背景；歌词前景、歌曲信息与控制区遵循 16dp 内容边距。导航本身、图标点击区域、按钮和滑条固有尺寸、系统栏 inset 不纳入数值替换。

## 实现与验证顺序

1. 原位更新完整原型及缓存版本，定向检查现有页面的边缘与弹窗，不另建审核页面。
2. 按已确认范围迁移 Compose 正式间距。
3. 音量不可拖动独立修复：将播放器准备状态纳入 Compose 观察，保证准备完成后音量控件会更新可用状态。先通过快照观察回归复现，再修复验证；不改变既有界面。
4. 仅执行相关检查；遵守用户最新要求，未另行指定构建验证时不额外打包 / 安装。完整原生视觉由用户审核。

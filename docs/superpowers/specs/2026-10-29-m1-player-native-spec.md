# M1：播放页原生实现规格

- 日期：2026-10-29
- 设计基线：正常布局采用原型 03 的 `774a6d6`（`revision=queue-fade`）；播放状态采用已确认修订 `608ddb2`（`revision=track-feedback`）。
- 确认性质：正常布局由用户“ok先暂时这样”暂定确认；播放状态修订于 2026-10-29 由“ok，这版没问题”确认，见 [状态确认记录](2026-10-29-prototype-playback-states.md)。
- 本文交付：将已确认设计映射到 Compose；尚未修改正式应用 UI，未构建或验收原生实现。

## 1. 范围与依据

覆盖 Android 有 / 无歌词播放页、Windows 左播放器 / 右歌词、同一份队列的自适应呈现，以及本次确认的播放等待 / 异常 / 结束反馈。搜索、音乐库、设置和超出该范围的新设计仍需先更新原型并由用户确认。

UI 依据为 [Google Expressive UX 研究](https://design.google/library/expressive-material-design-google-research)、[M3 颜色系统](https://m3.material.io/styles/color/system/overview) 及本机 m3-expressive 技能的 `tokens.md`、`layout.md`、`color.md`、`components/buttons.md`。其他播放器只作技术参考。

本文区分以下两类数值：

- **M3 规则**：触控目标至少 48 × 48 dp；颜色成对使用；常规文字对比度至少 4.5:1、大文字至少 3:1；形状 / 位置用 spatial 动效，透明度 / 颜色用 effects 动效。
- **RxPlayer 设计决策**：下述具体宽度、间距、控制组合、歌词窗口和遮罩参数来自暂定原型，是产品选择，不是 Google 规定的播放器模板。CSS px 作为基准密度下的 dp 设计参照，原生实现仍需按实际可用空间与字体缩放复核。

## 3. Android 两套布局

### 3.1 无歌词

从上到下为：返回 / 队列、封面、来源、标题 / 收藏、作者、分区控制卡、随机 / 循环。

控制卡的第一行是宽播放 / 暂停和下一首，第二行是上一首和进度 / 时间。这是由独立动作组成的自定义分区容器，不是 Material 的“主按钮 + 下拉菜单”SplitButton，也不是选择项的 Connected Button Group。

基准目标：控制卡内边距 16 dp、行列间隔 16 dp、切歌按钮 64 dp、外圆角 32 dp；原型在窄于 375 CSS px 时改用 12 dp 内边距 / 间隔、56 dp 切歌按钮和 28 dp 外圆角。正式实现采用可用宽度约束，保持至少 48 dp 的操作目标。外圆角与内嵌控件圆角分别设置。

### 3.2 有歌词

背景封面使用裁剪填充，左右铺满并绘制到系统状态栏后方。返回与歌词前景消耗真实 `WindowInsets`，不能照搬原型用于模拟状态栏的固定 120 px 上延量；底部控制避开手势导航区。

背景黑色遮罩由 72% 渐变到 86%；封面与遮罩一起在底部 96 dp 渐隐到当前 `surface`。歌词不能进入该淡出带。原型的 2 px 模糊只作效果参照：Android API 26～30 没有同等平台模糊能力时，保留压暗与渐隐，不为模糊引入截图或离屏位图循环。

歌词阅读区保留当前行及前后各两行，首尾不足用非交互留白保持当前行位置。原型按时长均分的时间戳不能带入真实歌词；正式高亮、点击跳转必须使用实际行时间。无有效时间戳的纯文本不能伪造同步。

歌词下方为标题 / 作者来源，右侧同排为队列和收藏，目标均至少 48 dp，间隔 8 dp。随后显示进度、时间和五按钮控制条，顺序固定为：

**上一首 → 随机 → 播放 / 暂停 → 循环模式 → 下一首。**

不保留 10 秒跳转、重复模式按钮、页头队列、“当前曲目”标题或“已暂停”横幅。播放 / 暂停由图标和可访问名称表达。

短屏与放大文字时优先保持完整控制目标；允许内容区域纵向滚动，避免硬套原型 900 px 高度。该适配需在原生实现后实测，当前不记为已通过。

## 4. Windows 与队列

左栏固定视觉宽度、右栏弹性填充。默认左栏 352 dp、栏间距 48 dp、水平内边距 32 dp；原型窗口宽度不超过 1000 CSS px 时为 300 / 32 / 24。左侧封面最大 280 dp，标题使用 32 sp / 40 sp 的层级。

左栏始终使用无歌词的两行控制卡，不因右栏是否有歌词切换成手机五按钮控制条；卡片下显示随机、循环和音量。右栏无歌词时呈现原型已有空状态，不伪造歌词。

原型不超过 760 CSS px 时上下堆叠；超过 1100 CSS px 时队列可停靠右栏。这两个阈值是暂定产品参数，不等于 M3 的 600 / 840 dp 断点。原生实现根据内容区实际宽度与缩放复核，不能根据操作系统名称推断窗口足够宽。

队列只有一份状态和一份可交互列表：

- 宽桌面：打开队列时替换右侧歌词，关闭时恢复歌词，不新增第三栏或重复弹窗。
- 窄桌面：复用同一队列内容，以模态侧面板显示。
- 手机：复用同一队列内容，以底部模态面板显示。

队列开闭、窗口改变、播放器展开 / 收起只改变呈现状态，不重建播放器或重置曲目 / 位置。模态状态限制焦点，关闭返回对应入口；停靠状态不阻断左侧控制。Esc / Android 返回先关闭队列，再退出展开播放页。

## 5. 颜色、排版与动效

应用导航保持品牌方案，播放器的强调角色来自当前封面：播放填充用 `primary / onPrimary`，辅助切歌和收藏按基线使用 `secondaryContainer / onSecondaryContainer` 或 `tertiaryContainer / onTertiaryContainer`，模式未选中用中性表面，选中同时改变语义状态和外观。

原型四张封面的 MCU 预计算结果只覆盖演示资源。在线封面取色须对实际解码像素量化和生成 light / dark 角色，按封面身份缓存；快速切歌时只接受仍属于当前曲目的结果。取色失败使用品牌角色，不把文件名或曲目序号当成颜色来源。

沉浸背景在浅色主题下也保持深色阅读区，歌词强调采用封面的深色方案 `primary`。外部底色仍跟随应用主题，渐变连接两者。正式图片、极端亮封面和对比度偏好需重新检查，不能以演示图片通过证明所有远端图片通过。

M3 现有层级：`headlineLarge` 为 32 / 40 sp，`headlineSmall` 为 24 / 32 sp，`bodyLarge` 为 16 / 24 sp，`titleLarge` 为 22 / 28 sp。播放器标题、紧凑标题及作者分别使用这些层级；当前歌词的加粗是 RxPlayer 强调选择，不把它误称为默认 `titleLargeEmphasized` 的字重。

通过 `MaterialExpressiveTheme` 注入 `MotionScheme.expressive()`；按钮形状使用组件 shapes API。自定义布局变化使用 theme spatial spec，颜色和淡入淡出使用 effects spec。遵循系统动画缩放；减少动态效果时状态仍清晰，不能只依赖动画表示选中。

## 6. Compose 映射与现有版本

保留 Kotlin 2.2.20、Compose Multiplatform 1.9.3、Material3 1.9.0-alpha04。本轮未修改依赖。JetBrains 对该组合的说明见 [1.9.3 发布文档](https://kotlinlang.org/docs/multiplatform/whats-new-compose-190.html)。

已从 Maven Central 下载确切版本的 sources JAR，检查以下 commonMain 声明存在，共 15 项；见 [检查证据与 SHA-256](../../evidence/m1/2026-10-29-material3-api.json)。这只证明源码声明存在，不证明当前工程链接或两端运行通过。

| 原型职责 | Compose 实现位置 / API |
|---|---|
| 两端布局选择与单一队列宿主 | `App.kt` 中协调；播放器内部保持单一外部状态输入 |
| 播放页、两套控制、进度与队列内容 | `ui/Player.kt`，使用 `Button`、`FilledIconButton`、`FilledIconToggleButton`、`Slider`，必要时按职责拆文件 |
| Expressive 主题、角色和取色结果 | `ui/Theme.kt`，`MaterialExpressiveTheme`、`MotionScheme.expressive()` |
| 封面裁剪、遮罩和渐隐 | `ui/Artwork.kt`，图片与遮罩同层处理，前景歌词独立 |
| 字体与按钮状态 | `Typography` 的 emphasized 属性、`ButtonDefaults.shapes()` 已存在；按原型角色选择，不能全局加粗 |
| 准备 / 缓冲 / 地址更新 | 在既有进度轨道内绘制不定缓冲效果；不额外显示 `LoadingIndicator` 或状态卡，具体原生 API 与轨道绘制能力需按锁定版本核对 |

不为实现播放器引入另一套播放器生命周期。现有 `AudioPlayer.load(ByteArray)` 与 `PlaybackState` 只服务 WAV 演示；流媒体契约及平台适配在技术验证后演进。

## 7. 状态与操作契约

此处为 PLAY-05 的业务契约与 `608ddb2` 已确认的视觉反馈；实现须以真实引擎事件驱动，不照搬原型的模拟定时器。

| 状态 | 数据与控制约束 |
|---|---|
| 未选择 | 不伪装当前曲目；播放、进度不可操作；时长未知不显示真实零时长 |
| 解析 / 准备 | 选择已更新、旧请求已取消；只在原进度轨道显示缓冲效果，无卡片或等待 toast；未知时间显示 `—:—` 并禁止拖动；主操作可取消，不提前标记正在播放 |
| 缓冲 | 同一轨道显示不定效果，保留已知时间及用户播放意图；主操作暂停等待后不得自动继续；不挤压歌词空间 |
| 播放 / 暂停 | 图标、可访问名称与引擎事件一致；去掉可见暂停提示并不删除暂停状态 |
| 地址更新 | 在原轨道显示缓冲效果；保留曲目、队列、位置和更新前的播放意图；主操作可取消，成功后此前暂停则仍暂停 |
| 结束 | 由真实结束事件及队列模式决定下一项；顺序播放到队列末尾直接停止，恢复播放图标，不显示完成卡或 toast；用户再次播放从头准备 |
| 失败 / 地址失效 | 仅 toast 提示，保留曲目身份、队列与恢复位置；主播放按钮提供重试 / 重新获取，toast 消退不影响操作；不无限重试 |
| 内容不可用 | 仅 toast 提示，可通过主操作再次查看；仍可切歌或从设置检查音源账号，不把登录等同于取得播放权限 |

状态至少包含：稳定内容身份、引擎阶段、播放意图、当前位置、可空总时长、可拖动能力、播放模式、收藏状态、歌词数据与队列呈现状态。来源解析得到的临时 URL / headers 属于播放输入，不持久化为内容身份；加载成功必须由引擎事件确认。

短提示采用应用内单条 toast / snackbar 呈现，沿用原型 3 秒消退的产品选择；语义通过可访问名称和状态同时保留。减少动态效果时，轨道保留可辨认的静态等待指示。轨道缓冲是产品定制，不宣称为原生 Slider 的标准缓冲 API。

## 8. 交互验收清单

- [ ] Android 真机：系统状态栏 / 手势区、返回、短屏 / 横屏与 2 倍文字；歌词和控制均可访问。
- [ ] Windows：键鼠、窗口缩放、Tab 顺序、焦点可见、悬停提示；文本输入中空格不控制播放，其他适用区域空格播放 / 暂停。
- [ ] 队列：宽窄切换只有一份列表；开闭保留进度、选中项和焦点；播放页返回后仍可继续当前任务。
- [ ] 状态：真实准备、缓冲、暂停、结束和失败均与引擎一致；未审核的视觉状态先走原型。
- [ ] 颜色：多张真实封面、深浅主题、取色失败 / 延迟、快速切歌；无错曲配色与不可读组合。
- [ ] 所有核心交互目标至少 48 dp，触摸、键盘与读屏名称 / 状态一致。

歌词服务仍属于既定 P1。M1 可以定义有歌词的界面契约和测试夹具，不能把演示歌词写进真实来源结果，也不把保留歌词布局等同于已经交付在线歌词能力。

# 歌曲信息补全与歌词 / 封面提案

状态：用户已确认并授权正式接线。日期：2026-11-06。确认基线 `dc7316e`，原话「确认，按此方案接入双端」。入口：现有 `design/prototype-v3/index.html`，当前缓存版本 `song-metadata-confirmed-20261106`。确认仅覆盖本提案的新入口和补全 / 回退范围，不代表原生视觉验收通过。

## 目标与方案

让 Bilibili 音乐视频在保持原视频 / 具体 cid 播放的同时，显示匹配歌曲的歌名、演唱者、专辑封面和可用歌词。

推荐「明确时自动补全，不确定时保留原信息并允许选歌」。全手动选歌更可靠但每次操作较多；音频指纹需要额外服务与音频处理，本批不引入。先以标题 / 分 P / 简介的明确线索落地，不引入大模型或用户 API Key。

## 数据与匹配规则（正式接线提案，尚未实现）

1. 读取具体分 P 标题、总标题、简介中的「演唱 / 歌手 / 原唱 / 翻唱」等明确字段；UP 主仅作为发布者，不能直接认作演唱者。合辑只匹配已选 P，信息不足则停止自动处理。
2. 清理标题中的清晰宣传标记，保留 live / 现场 / 翻唱 / 伴奏 / 混音 / 语言等版本信息；不把原唱自动写成本次翻唱者。
3. 查询歌曲库，比较歌名、演唱者、版本、时长。候选须唯一、歌名 / 演唱者有明确依据、版本无冲突，并且歌曲时长与该 P 差值不超过 2 秒，才尝试自动应用。**2 秒是 RxPlayer 本批的保守选择，不是自动识别准确性保证或 Google 规范。**同名多候选、版本未知 / 冲突、翻唱、现场、剪辑和串烧不自动应用原版同步歌词。
   正式实现收紧：演唱者完整集合一致；标题含中英文括号时不推定括号是可忽略别名，直接保留人工选择，包括真实样本的「你我怎么两清」。重制 / 未知录音限定同样不自动应用；人工选择仍检查已知版本、演唱者和时长冲突。此为已确认“不确定保留原信息”的保守实现，不引入按单首歌白名单。
4. 首批提案：网易云提供候选与专辑封面 / 歌词，LRCLIB 补歌词；歌词来源仍核对标题、作者、版本与时长，不能只凭曲名跨源拼接。
5. 首批同步 LRC 按毫秒解析；仅返回纯文本时视为暂无同步歌词，沿用无歌词布局，不编造逐行时间。歌词缺失和图片缺失分别回退，不互相阻塞。纯文本专用展示、歌词偏移编辑、翻译 / 逐字歌词不在首批范围。
6. 自动补全不阻塞播放；网络失败保留原视频信息，不反复 toast。用户主动搜索 / 应用失败时沿用短提示；没有候选时在选择界面允许改词。
7. 匹配结果独立关联稳定的 Bilibili 视频 / cid 身份，保留原标题、发布者、视频封面与来源信息。更换信息不改队列顺序、音频地址、实际时长、进度或暂停意图，不触发重新播放。
8. 正式结果记录来源与外部歌曲 ID，缓存可用信息及用户选择；切歌后的旧请求不能覆盖新曲目。恢复视频原信息会清除该项覆盖，避免下一次自动请求立即重新覆盖。具体 schema / 测试计划在确认后编写。

## 完整原型本次修改

- 播放页右上角同源 `more_horiz` 图标进入「匹配歌曲信息」；具体分 P / 单视频的现有更多菜单也有该项。总合辑菜单仍先选 P。
- 选择面板展示当前视频标题、UP 主和实际时长，提供歌名 / 歌手输入、搜索、候选列表。候选展示歌曲名、演唱者、版本、时长及歌词可用性，选中后应用并返回。
- 选择成功的播放页 / 迷你播放器更新歌名、歌手、封面；歌词复用已确认双端有 / 无歌词布局；选择 / 恢复均保留进度与播放状态。
- 已应用时可「使用视频原信息」；取消或关闭不改当前匹配。没有候选时展示简单空结果，允许修改搜索词。
- 原型中的「夜航」两项候选、封面与歌词均为已有原创演示素材。面板明确标注未联网；选择后模拟展示结果，不表示完成自动识别或原生接线。
- 原型搜索结果和队列仍保留原视频标题 / 发布者，便于追溯视频版本。本批演示只覆盖播放器与迷你播放器补全；正式搜索结果也保留源视频信息，不将匹配歌词当作另一个音频来源。

## 设计依据

沿用 m3-expressive 技能的 containment / feedback 参考：复用现有自适应 sheet、列表、文本输入和按钮，使用既有 Material 角色色、焦点与关闭规则；候选列表作为明确的选择任务。入口位置、版本校验、自动补全和保留原视频信息是 RxPlayer 的产品决定，不宣称为 Google 强制规定。

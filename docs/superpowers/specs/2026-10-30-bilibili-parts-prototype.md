# Bilibili 搜索与分 P 交互审核

- 状态：待用户确认；仅原型。来源核心 `5ebec5c` 已以 `2e01efe` 合入 main；这不代表新分 P UI 获得确认或已经接入产品。
- 预览：`http://127.0.0.1:8767/prototype-v3/bilibili-review.html`，可切换 Windows / Android、深浅主题。
- 依据：现有原型 03 的搜索 / 浮岛结构、m3-expressive 中 Google 对话框与列表指导。沿用现有颜色角色和模态焦点约束；分 P 行的尺寸 / 分组及即时操作为 RxPlayer 产品决策，不声称是 Google 固定布局。

## 本轮待确认范围

1. 单 P 继续直接播放，多 P 内容点击播放后先选择具体 P；取消不改变当前音频或队列。
2. 从更多菜单加入队列 / 下一首播放时同样先选 P；确认后只加入对应 P，不中断当前播放。
3. 同一视频不同 P 以独立 ID 入队，显示 P 编号与标题，避免互相覆盖；具体 cid 由正式来源层解析，不保存临时播放 URL。
4. 当前 P 具有选中提示；弹窗有关闭 / 取消，焦点进入列表、Tab 留在弹窗、Esc 关闭并回到原触发入口。
5. 本轮 Bilibili 预览中其他音源禁用；批量歌单 / 收藏播放未启用，避免未定义的多 P 批量取消副作用。这些功能不是本轮新增设计的隐含交付。

原型采用原创示例内容和三条分 P 样本，均为模拟交互；正式来源核心的 36 分 P 真实样本是另一层技术证据。页面没有真实请求或真实播放，也不把原型中其余账号 / 歌单模拟能力当成产品已完成。

## 定向检查

- PC 900 / 1440 CSS px、Android 320 / 390 CSS px，各深浅主题共 8 组：选项目标、弹窗边界、无横向溢出、初始焦点与取消焦点恢复通过。测试临时去掉 iframe 外边框并核对实际视口宽度，避免把外框尺寸当作内容宽度。
- 多 P 选择播放、普通入队、下一首入队、不同 P 并存、取消不改变当前播放 / 队列、菜单转选择后的 Esc、Tab 焦点环通过。
- 源码审查发现方向键可绕过禁用来源、批量播放预先覆盖队列两项问题；已修正为方向键仅遍历可用来源、M2 禁用未定义的批量入口，并完成针对性复测。外源歌单条目也不能播放或入队。
- 非 M2 默认原型仍保留 3 个可选音源 / 3 项初始队列，普通播放不触发分 P 选择；默认音源键盘切换复测通过。
- JS 语法及 Git 空白检查通过；未修改正式 UI、未因本轮原型更新重复构建应用。

需要用户确认本轮双端搜索 / 分 P 流程后，才能进行对应正式 UI 接线。按 AGENTS.md 的原型规则，仅推送审核分支，不将这批原型先合并 main。

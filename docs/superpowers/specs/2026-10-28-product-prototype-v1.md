# RxPlayer 产品原型 01：审核说明

状态：**已提出，待用户审核**。本文件不是批准记录。

## 背景修正

此前构建并启动的 Compose 工程是技术与组件验证样例，用来验证双端入口、Expressive API 和本地音频适配。用户没有确认其为产品原型，不能在规划中沿用为已确定的产品设计。

本轮先交付可审核的产品原型，再由用户决定结构与视觉是否成立。用户确认前，不以旧验证样例的补验收代替产品原型设计，也不按未经批准的页面推进原生产品 UI。

## 交付物

- [交互原型](../../../design/prototype-v1/index.html)。
- [原型使用说明、规范来源及设计决策](../../../design/prototype-v1/README.md)。

本轮仅表达设计，不接入在线音源、不实现真实账号和播放服务、不修改现有 Compose 产品代码。浏览器形式是审核载体，原生技术路线保持不变。

## 审核内容

1. 一级入口“搜索、音乐库、设置”是否成立。
2. Android 迷你播放条、展开播放页、队列和菜单是否方便理解及操作。
3. Windows 内容区域、播放队列辅助面板与控制条的分工是否清晰。
4. 音源选择、歌曲 / 视频版本、收藏和歌单是否容易辨识。
5. 准备、暂停 / 播放、无结果、网络错误、登录失效等状态表达是否合理。本版重点呈现已知时长的暂停 / 播放及搜索异常，完整缓冲动效留待后续设计修订。
6. 深浅主题、字号层级、按钮强调、形状反馈和整体视觉方向是否接受。

## 方案取舍

- 当前提案：任务优先的三入口结构，搜索直接可见；手机展开播放，桌面显示辅助队列。
- 保留为可能调整方向：用户若更重视沉浸收听，可将正在播放提升为更显著入口；若更重视个人收藏，可将音乐库设为默认页。它们不是本轮同时实现的额外方案，也不代表当前结构已锁定。
- 选择当前提案的理由：与“搜索视频平台音乐并播放”的首要任务一致，减少搜索路径，避免用大幅宣传卡片占据首屏。

## 审核与后续

- 交互原型和文档完成检查后提交推送到 `codex/prototype-review`，供用户审阅。
- 因用户明确要求“我来审核”，本阶段在用户审核前保持待审核状态，不自动将设计标记为批准或合并主分支。
- 用户反馈后，在同一设计分支集中修订；获确认后记录范围和版本，再合并并拆解原生实现任务。
- 技术验证样例的未测场景保留为技术记录，按后续实现与质量阶段安排，不阻塞本轮出产品原型。

# Windows 浮岛播控栏：确认与实现

## 用户确认

2026-10-30 用户明确：“可以，就使用第三种浮岛样式，其他两种可以去掉了，然后更新到windows端”。确认基线为 `cf8e74b`，包含分组顺序、窄竖向音量浮层以及透明底色的队列图标。原型现仅保留该方案，旧审核地址仍可访问，A / B 入口、渲染分支及专属样式已移除。

入口：`design/prototype-v3/transport-review.html`；常规原型 Windows 底栏也采用确认样式。

## 确认范围

- 底栏从右侧内容区起始，左侧导航贯穿到底。
- 左：封面、歌名、歌手；中：横向进度及前后时间；右：随机、上一曲、播放、下一曲、重复、音量图标、播放队列。
- 三个浮岛，常规桌面原型高度 88 CSS px。主播放使用封面 primary / on-primary 角色色，其余操作降低强调；打开的队列只改变图标颜色，不加圆形色块或加粗填充。
- 音量点击向上展开窄竖条与下方百分比；外部点击或 Esc 收起，保留音量。提供键盘调节与焦点恢复。
- 较窄窗口进度移至第二行。原生更窄窗口（内容列不足 620 dp）保留三行并允许操作组横向滚动，确保按钮可达；该处理是确认布局的响应式实现。
- 准备 / 缓冲 / 获取地址仍仅在轨道中反馈，错误和末尾停止沿用既有状态约定。

尺寸、断点和容器组合为 RxPlayer 产品决策，并非 Google 的播放器规范。依据 m3-expressive 中按钮、滑轨、颜色角色和布局指导，不采用其他播放器的整套视觉设计。

## 正式实现

- `ui/DesktopMiniPlayer.kt`：三浮岛、进度、播放操作、窄音量 Popup 和窗口适配。
- `App.kt`：仅 `isDesktop` 选择新组件，回调复用现有 PlaybackState；Android 沿用 MiniPlayer。
- `ui/Player.kt`：复用必要辅助函数，新增颜色参数提供原行为默认值，不改变 Android / 展开播放页默认样式。
- 原生模型继续为本地演示音频，不包含在线搜索、持久化或后台播放。

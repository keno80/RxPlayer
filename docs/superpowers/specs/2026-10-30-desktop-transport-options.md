# Windows 底部播控栏：三方案审核

状态：待用户选择与确认，不实施 Compose，不合并主分支。

## 目的与范围

用户指出浏览 / 搜索页面底部播控栏占比过大，要求设计几版比较。本轮只提出 Windows 底部迷你播放器的三个布局；Android、独立展开播放页及正式应用不变。

入口：`design/prototype-v3/transport-review.html`。顶部切换 A / B / C 和深浅主题，复用原型 03 的模拟播放、进度、队列与封面角色配色。未传 `transport` 参数时保留旧原型。

## 方案

| 方案 | 常规桌面高度（CSS px） | 组织方式 | 权衡 |
|---|---:|---|---|
| A 单行横向，推荐 | 80 | 曲目信息、五个播控、进度、音量 / 队列依次同排 | 内容空间最多；进度与操作的视线略偏离页面中轴 |
| B 居中双层 | 112 | 曲目在左、按钮及进度居中、辅助操作在右 | 保留上下留白和按钮间距，节省高度少于 A |
| C 分组浮岛 | 88 | 播放信息、进度、完整播控三个容器 | 按用户指定顺序组织，右侧汇总全部播放操作 |

以上高度、区域比例、断点和容器组合均为 RxPlayer 自身设计决策，并非 Google 的播放器规范。1000 CSS px 及以下让进度独立成行，高度 112 px，音量沿用展开播放页入口；避免挤压图标操作目标。

## 设计依据

- M3 / M3 Expressive：通过主次颜色、形状和容器引导注意力；主播放使用封面提取的 primary / on-primary；其他操作降低强调，选中模式采用 secondary 容器角色。
- 采用图标按钮及切换状态；主播放为独立的高强调操作，不把整排传输操作误称为筛选用的 connected button group。
- 滑轨保持足够输入命中高度，缩小可见轨道和拇指；常规目标至少 48 CSS px 高。全部尺寸是网页原型表达，原生实现需另行核对 Compose API。
- 参考技能 `m3-expressive` 的 `components/buttons.md`、`components/input.md`、`components/bars.md`，及 [Google Expressive 研究](https://design.google/library/expressive-material-design-google-research)。未采用第三方播放器 UI。

## 音量图标与浮层

用户要求把常驻音量条改为图标，点击显示滑条。本轮仅调整 C：右侧“重复”与“列表”之间保留音量图标，点击后向上打开包含百分比与横向滑条的浮层。音量为零时图标显示静音；再次点击、点击外部、焦点移出或 Esc 收起，Esc 返回音量按钮焦点，重新打开保留当前值。Esc 优先关闭音量浮层，不连带关闭已有队列。

四种宽度 1440 / 1150 / 900 / 800 × 深浅主题共 8 组检查通过：默认收起、点击展开、滑条 / 百分比同步、Esc 焦点恢复、外部关闭、重新打开保留值、浮层在窗口内及队列状态未改变。截图工具本轮超时，未将其记录为目视复核成功；交互与边界依据浏览器实际 DOM 检查。浮层尺寸与位置是产品决策，不是 Google 播放器规范。正式应用未修改或构建。

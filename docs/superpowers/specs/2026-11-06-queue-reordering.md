# 播放队列手动排序

日期：2026-11-06；分支：`codex/queue-reordering`。

## 范围与确认

用户要求先做“1 原型、2 共享逻辑及双端接线”，不包含 Bilibili 异常场景收口。本批先在唯一完整原型 `design/prototype-v3/index.html` 更新排序设计，定位参数 `?device=desktop&theme=dark&view=queue`；Android 用同页平台切换。不新建独立审核页面。

**确认范围：** 用户先要求完成原型及正式接线，审阅第一稿后指定“直接在后面显示拖拽 icon，不需要点排序”，随后以“按简化版继续”确认此方向。已先将唯一原型更新为常驻手柄，正式实现按该范围等价接线；上移 / 下移作为点按手柄后的非拖动替代，不新增排序模式。原型与正式功能完成状态分别记录。

## 设计选择

考虑始终显示手柄、仅用上移 / 下移、显式排序模式三种方式。用户明确要求“直接在后面显示拖拽 icon，不需要点排序”，现采用每行末尾常驻手柄，保留现有封面、标题、当前标记和移除按钮。拖动和点按手柄后的上移 / 下移均可完成同一操作，减少触屏与辅助输入对精细拖动的依赖。

- Windows 沿用同一队列侧栏，Android 沿用同一底部队列面板，不增加第二个队列窗口。
- 不存在“排序 / 完成”模式或额外开启步骤，打开队列即可拖动。
- 拖动仅由右侧手柄开始，曲目行显示拖动状态与目标插入线；列表边缘可滚动。松手时提交排序，拖出列表、Esc 或指针取消不改变顺序。
- 曲目信息仍用于播放。点按手柄展开该项的上移 / 下移工具，首尾方向禁用；手柄获得焦点后，上下方向键可直接移动该项。移动后保留焦点、播报新位置，当前播放标记始终跟随曲目身份。展开工具本身不触发播放。
- 排序立即生效；关闭队列或收起移动工具保留已经提交的顺序，不是撤销操作。
- 当前曲目可移动，播放身份、位置、暂停 / 播放意图、循环 / 随机开关均不因移动而改变。下一首按调整后的实际顺序前进。
- 随机模式使用稳定的本轮顺序，队列显示此实际顺序；手动排序调整本轮及手动队列，不暗中关闭随机模式。重新开启随机才生成新一轮顺序。
- 空队列无手柄，单曲队列手柄禁用。默认模拟队列含五项及具体分 P，便于从完整入口直接审核。

## Google 指导与 RxPlayer 决策

Google M3 列表指导：封面 / 文字 / 辅助操作保持一致位置，内容区域优先，拖动可用状态与层级反馈区分；M3 交互目标基线为 48dp。原型沿用现有主题颜色角色，排序选择使用 primary 轮廓，当前播放仍用现有底色和音符标记；新增操作使用 48 CSS px 的命中区域。原型像素映射不是跨平台单位等价承诺。

RxPlayer 自身决策：常驻手柄、点按后的移动工具、手动排序对本轮随机顺序的语义、插入线与边缘滚动参数均属于本产品选择，不称为 Google 固定规格。手柄使用官方 Material Symbols Rounded `drag_handle` SVG，避免字体子集未收录的 ligature 外露；上 / 下箭头复用已收录的 `arrow_back` 旋转，不扩字体依赖。

来源：[M3 Lists](https://m3.material.io/components/lists/guidelines)、m3-expressive 技能的 containment / interaction 参考、[W3C 拖动的非拖动替代](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)、[Google drag_handle SVG](https://github.com/google/material-design-icons/blob/master/symbols/web/drag_handle/materialsymbolsrounded/drag_handle_24px.svg)。

## 第 2 步实现约束

确认后，在共享 PlaybackState 按稳定曲目 ID 重排；不重新选曲、不调用 load / seek、不重置解析或播放意图。按当前显示的有效顺序处理随机模式，并保存必要的顺序身份，使重开后顺序与当前项一致、保持停止恢复。双端正式队列复用同一移动操作，按确认方案接手柄及非拖动按钮。

定向验证：普通 / 随机 / 循环顺序，具体 cid 身份，当前项与播放位置保持，首尾 / 无效移动，下一首与自然结束，顺序写入及重开恢复。仅做相关测试；遵循用户最新“不额外构建验证”的约定，不安装测试 APK。

原型模拟数据不持久化，刷新会重置；不能用本批浏览器演示声称正式排序或恢复已完成。

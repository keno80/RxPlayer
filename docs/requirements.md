## 2. 产品目标

用户可以在同一个应用里，从三个平台查找内容，选择希望收听的版本，加入同一播放队列，并在电脑或手机上连续收听。

核心流程：

1. 打开应用，选择音源并输入关键词，或粘贴内容链接。
2. 查看带有来源、作者和时长的结果，选择曲目播放。
3. 使用播放队列、收藏和本地歌单组织内容。
4. 在 Android 锁屏、切到后台，或在 Windows 最小化应用后继续收听。
5. 再次打开应用时恢复音乐库、队列和上次位置，由用户决定是否继续播放。

首版以“搜索到内容并稳定收听”为主任务。首页宣传、装饰和推荐不能妨碍搜索、曲目识别与播放控制。

## 3. 版本范围与优先级

| 优先级 | 定义 | 内容 |
|---|---|---|
| P0 | 首个可用版本必须具备 | 三音源的真实搜索与播放、链接识别、统一队列、本地收藏和歌单、状态恢复、必要登录、双端系统播放能力、Expressive 设计与可访问性 |
| P1 | 核心闭环稳定后扩展 | 平台歌单与收藏夹读取、更多元数据搜索、歌词、歌单导入导出、缓存管理、更多音频输出设置 |
| P2 | 根据实际需求另行排期 | 可管理的离线下载、跨设备同步、平台歌单写入、个性化推荐、一起听 |

P0 全部交付前，阶段版本使用“原型”或“预览版”描述。只接通一个或两个音源，不视为完成三音源首版。

首版不覆盖 macOS、iOS、浏览器客户端和公共云端账号服务。不因参考项目具有某功能就自动加入 RxPlayer。

## 4. 功能需求

### 4.1 音源与搜索

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| SRC-01 | P0 | 网易云歌曲搜索与真实音频播放 | 能搜索歌曲、展示可用结果并播放原平台允许当前用户收听的内容；仅提供歌词或把歌曲匹配到 B 站不算完成 |
| SRC-02 | P0 | Bilibili 视频搜索与音频播放 | 关键词结果可以直接播放音频；识别 BV / AV 号及常见视频链接；多分 P 内容可以选择分 P |
| SRC-03 | P0 | YouTube 搜索与音频播放 | 默认规划包含公开视频关键词搜索和常见视频链接识别；展示可用结果并播放音频。YouTube Music 能力单独标识，不能以其曲库搜索代替全部 YouTube 需求 |
| SRC-04 | P0 | 分平台搜索 | 首版由用户明确选择音源；支持清空、重新搜索、分页、无结果、加载失败与重试；保留各音源的关键词和结果位置 |
| SRC-05 | P0 | 结果与版本识别 | 显示标题、作者 / 歌手、时长、封面及来源；现场版、翻唱、合集等保留原始信息，不伪装成同一录音版本 |
| SRC-06 | P0 | 链接识别 | 识别支持的来源和内容类型，展示解析结果；不支持的链接给出具体说明；解析失败不自动切换成无关曲目 |
| SRC-07 | P0 | 能力与权限反馈 | 登录要求、地区限制、内容下架、试听、接口失败分别显示可理解状态；不能把不可播放结果标成完整可播放内容 |
| SRC-08 | P1 | 平台内容浏览 | 按实际可用能力提供网易云歌单、B 站收藏夹 / 合集、YouTube 播放列表读取；每项能力独立验收 |

搜索和播放通常属于不同接口能力，应分别验证。三个平台先各自跑通，再考虑聚合搜索；首版不自动跨源替换用户选择的内容。

### 4.2 播放与队列

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| PLAY-01 | P0 | 流式音频播放 | 支持三音源实际返回的音频格式、鉴权请求头及过期链接；边缓冲边播放，不要求先下载完整内容 |
| PLAY-02 | P0 | 基础控制 | 播放、暂停、继续、上一首、下一首、拖动进度、结束后按播放模式处理；已加载曲目显示真实总时长 |
| PLAY-03 | P0 | 统一队列 | 三个平台内容可加入同一队列；支持立即播放、下一首播放、追加、删除、清空和排序；当前曲目与队列位置一致 |
| PLAY-04 | P0 | 播放模式 | 顺序、列表循环、单曲循环和随机；随机顺序可以在队列中理解，连续操作不串曲 |
| PLAY-05 | P0 | 明确的播放状态 | 区分未选择、准备中、缓冲、播放、暂停、结束和失败；未加载时不显示虚假的“正在播放”或把未知时长展示成真实零时长 |
| PLAY-06 | P0 | 失败与中断恢复 | 快速切歌只保留最后一次选择；网络失败、失效链接、音频设备异常都有反馈；重试保留用户队列，不无限重试 |
| PLAY-07 | P0 | 位置与任务连续性 | 保存当前曲目、队列、模式和位置；重启后呈现可恢复状态，默认不自动发声；旋转、调整窗口和展开 / 收起播放器不重置当前任务 |
| PLAY-08 | P1 | 歌词与补全 | 支持可用歌词、偏移和手动匹配；明确歌词来源与匹配结果；无歌词不影响播放 |

播放地址是临时资源。持久化来源及内容标识，重新播放时按需要解析地址；不把失效 URL 当成永久曲库数据。

### 4.3 音乐库与本地数据

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| LIB-01 | P0 | 收藏与本地歌单 | 收藏 / 取消收藏，创建 / 重命名 / 删除本地歌单，增删和排序曲目；重启后数据保留 |
| LIB-02 | P0 | 最近播放 | 记录真正开始播放的内容；能重新进入播放；失败请求不记为成功播放 |
| LIB-03 | P0 | 音乐库组织 | 区分收藏、歌单和最近播放；搜索及空状态与当前分类一致；音源暂不可用不删除本地收藏 |
| LIB-04 | P0 | 内容身份 | 不同来源及不同分 P 使用稳定、可区分的标识；同名歌曲不被错误合并 |
| LIB-05 | P1 | 导入导出 | 可导出和恢复本地歌单及设置；包含格式版本，不导出账号凭据；导入失败不破坏原数据 |

首版的“本地音乐库”指本地保存的来源引用、歌单和播放记录，不等于完整的本地音频文件扫描器。

### 4.4 账号与设置

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| AUTH-01 | P0 | 按需登录 | 不强制创建 RxPlayer 账号；音源需要登录时提供明确入口；匿名可用能力可独立使用 |
| AUTH-02 | P0 | 登录状态管理 | 显示已登录、已过期及未登录状态；支持退出和重新登录；实际登录方式通过各来源技术验证后确定 |
| AUTH-03 | P0 | 凭据保存 | 凭据仅用于对应来源请求，使用系统安全存储；不进入日志、歌单导出或源码仓库；退出后清除对应凭据 |
| SET-01 | P0 | 外观与播放设置 | 跟随系统 / 浅色 / 深色、曲目配色、播放恢复策略；更改后立即生效并持久化 |
| SET-02 | P1 | 存储与音频设置 | 查看和清理可重建缓存，选择可用音频输出；清缓存不清歌单、历史和账号 |

登录方式、可用音质和平台歌单能力以实际接入验证为准；产品只呈现已经验证支持的选项。

### 4.5 平台能力

| 编号 | 平台 | 优先级 | 需求与验收条件 |
|---|---|---|---|
| SYS-01 | Android | P0 | 使用适合流媒体的播放服务；锁屏和后台保持播放；通知 / 锁屏支持播放、暂停、切歌，并正确呈现曲目信息 |
| SYS-02 | Android | P0 | 正确响应音频焦点、来电和耳机断开；暂停和恢复行为可理解，不在不合适的时机自行发声 |
| SYS-03 | Windows | P0 | 窗口最小化后持续播放；支持系统媒体控制、媒体键和应用内空格播放 / 暂停；文本输入期间不抢占空格 |
| SYS-04 | Windows | P0 | 提供托盘入口和明确退出行为；关闭窗口是否保留播放可配置；退出后释放音频资源 |
| SYS-05 | 双端 | P0 | 兼容键鼠、触摸、软键盘与窗口变化；界面布局、安全区和播放状态保持正确 |

当前原型的 Android 退后台暂停、Windows Java Sound 播放 PCM 均为验证阶段实现，不等同于上述成品能力。

## 5. 信息架构与 Material 3 Expressive

### 5.1 建议的信息架构

首版建议提供三个真实一级入口：

- **搜索**：音源选择、关键词 / 链接输入、结果及搜索历史。
- **音乐库**：收藏、歌单和最近播放。
- **设置**：外观、播放行为、音源账号和应用信息。

“正在播放”和队列属于当前播放任务：手机通过迷你播放器展开，桌面在空间允许时作为辅助面板呈现，不机械增加成一级导航目的地。当前“发现”页的欢迎卡片可作为轻量辅助内容；个性化推荐不属于首版承诺。

以上为建议的信息架构，用于解决当前两个入口硬套导航组件的问题，不意味着为了满足组件数量添加空页面。

### 5.2 必须满足的设计条件

| 编号 | 要求 | 验收方式 |
|---|---|---|
| UI-01 | 双端采用真正的 Material 3 Expressive 设计系统 | 使用包含所需 API 的组件版本，统一主题、颜色角色、排版、形状和动效；仅使用大圆角或 `MaterialExpressiveTheme` 不算完成 |
| UI-02 | 组件选择符合功能和平台 | 按入口数量和窗口空间选择导航；选中与未选中状态明确；按钮、筛选、输入、弹层等有完整交互反馈 |
| UI-03 | 按窗口空间自适应 | 参考 compact <600 dp、medium 600–839 dp、expanded 840 dp 起的布局指导；具体播放面板出现条件由内容空间决定并记录为产品设计决策，不能直接把窗口宽度等同于设备类型 |
| UI-04 | 颜色与排版可访问 | 正确成对使用颜色角色；普通文字对比度至少 4.5:1、大文字至少 3:1；不能仅凭主题函数名称假设自定义色值合格 |
| UI-05 | 触摸与文字缩放 | 交互目标至少 48 × 48 dp；系统文字放大到 2 倍时，核心标签和播放操作仍可访问；窄屏、横屏、键盘弹出时不遮挡必要操作 |
| UI-06 | 动效服务于状态与注意力 | 位置、尺寸和形状变化使用空间动效；颜色和透明度变化使用效果动效；低动画设置下仍能理解状态 |
| UI-07 | 核心任务优先 | 搜索、曲目和播放操作优先于宣传卡片；播放器正确呈现准备、播放、暂停和错误；空状态包含可执行的下一步 |
| UI-08 | 双端交互完整 | 桌面有合理 Tab 顺序、可见焦点、适用的悬停提示、空格控制和弹层 Esc 关闭；手机尊重系统返回、安全区和软键盘 |

设计依据：[m3-expressive 技能与参考资料](https://github.com/abhixv/google-m3-expressive-design-skill/tree/main/skills/m3-expressive)。数值、组件行为和平台可用性按相关参考及工程所锁定的实际 API 核对；参考图片用于视觉对照，不作为测量数值的唯一来源。

## 6. 技术与数据边界

- 共享层负责来源模型、搜索、队列、音乐库、播放状态和主要 UI；系统播放器、媒体会话、凭据存储、托盘等保留平台实现。
- 三个音源采用独立适配，输出统一模型；能力不足单独反馈，一个来源失败不阻塞其他来源。
- 内容标识至少包含来源、来源内 ID，按需要包含分 P / 版本信息。播放地址与请求头只作为解析结果使用。
- 生产音乐库使用有版本迁移能力的本地数据库；主题等轻量设置持久化保存。实现库在对应阶段按双端支持和维护成本选定，不预先建立复杂存储框架。
- Windows 成品播放引擎必须通过网络音频和三来源格式验证。现有 Java Sound 仅覆盖原型 WAV，不作为流媒体方案的验收依据。
- 原型可以使用演示数据，但生产搜索入口不能混入未标注的假结果；参考其他项目的行为和边界，保持自身实现与依赖来源清晰。
- 首版没有中央账号或媒体转发服务；跨设备同步与公共服务需单独设计。

## 7. 首版验收与质量要求

P0 的验收在 Windows 和 Android 分别记录，不以共享代码替代平台验证：

1. 每个平台均完成三音源的关键词搜索、链接解析、真实播放与内容不可用场景。
2. 两端分别验证跨源队列、快速切歌、拖动进度、播放结束、断网 / 恢复、链接过期及重新登录。
3. 收藏、歌单、设置、队列和位置在重启后按约定恢复；升级不破坏既有数据。
4. Android 验证后台、锁屏、通知、耳机和音频焦点；Windows 验证最小化、托盘、媒体键、空格和退出。
5. 完成 UI-01 至 UI-08 的双端设计验收；同时记录确切版本、窗口 / 设备条件、截图与未通过项。
6. 用合法可访问的测试内容形成来源样本集，包含普通内容、长标题、合集 / 分 P、权限不足、下架及失败案例；不把“找到搜索结果”当作“可播放”证据。

启动耗时、内存、首帧和缓冲表现先在目标机器上建立基线，再制定发布阈值；本文不虚构尚无测量依据的性能承诺。

## 8. 当前实现与验证记录

截至 2026-10-28：

- 已有独立 Kotlin / Compose Multiplatform 工程、Expressive 主题和双端入口。
- 已实现演示搜索、来源标签、收藏、主题、自适应布局及三段原创 WAV 的播放适配；在线音源和持久化尚未接入。
- Android Debug APK 已成功构建、安装到已连接真机并启动；当时确认应用在前台，未发现启动崩溃。
- Windows 桌面目标已成功编译并打开窗口。
- 已进行双端部分视觉检查和源码核对；桌面空格播放未响应，导航、初始播放状态和嵌套圆角存在改进项。
- 界面检查因用户按 Esc 停止。手机键盘弹出状态、展开播放器、桌面窄窗口及完整播放交互尚未完成验收。

因此，当前状态为“原型可启动、部分设计审查完成”，不是 P0 已交付，也不是双端完整验收通过。

## 9. 范围建议的调整规则

当前默认先交付本地优先的三音源收听闭环，P1 / P2 不阻塞首版。若后续明确需要离线下载、同步、平台歌单写入或推荐，应先调整优先级及里程碑，不在实现中顺手扩展。

YouTube 的默认范围按 SRC-03 保留普通视频搜索和链接播放；若用户明确只需要 YouTube Music，再收窄并记录。登录方式和 Windows 引擎在技术验证阶段形成结论，未验证前不展示为已支持能力。
